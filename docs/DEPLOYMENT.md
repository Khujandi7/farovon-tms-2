# FAROVON TMS 2.0 — запуск, Supabase, GitHub и Vercel

## 1. Локальный запуск

Требуется Node.js 22 (см. `.nvmrc`, минимум 20.9) и npm.

```bash
npm ci
cp .env.example .env.local      # заполнить значения из Supabase (раздел 2)
npm run dev                     # http://localhost:3000
```

Проверки:

| Команда | Что делает |
|---|---|
| `npm run typecheck` | TypeScript (strict) |
| `npm run lint` | ESLint (next/core-web-vitals + typescript) |
| `npm run test` | Vitest: логика авторизации, маршрутов, ролей, KPI, компоненты |
| `npm run test:e2e:build && npm run test:e2e` | Playwright: сборка под локальный mock Supabase (`e2e/mock-supabase.mjs`), десктоп и телефон |
| `npm run build` | Production-сборка |
| `npm run test:db` | SQL-тесты Phase 1 / 1.5 на локальном PostgreSQL 16+ |
| `npm run check` | typecheck + lint + test + build |

Если Playwright не может скачать браузер, укажите установленный Chromium: `PW_CHROMIUM_PATH=/путь/к/chrome npm run test:e2e`.

### 8.4. Как добавить источник и как работает синхронизация
Сотрудники → Импорт → «Google Sheets» → ссылка → лист → предпросмотр (строка заголовков определяется автоматически или выбирается) → соответствие колонок →
отметить «Сохранить как источник» → dry run. Затем «Синхронизировать сейчас» на панели источников. Расписания и внешнего cron нет — только ручной запуск.

Синхронизация = чтение листа сервером → `import_stage` (dry run) → если нет строк на ручную проверку — `import_commit` → `record_source_sync`.
Сопоставление: табельный номер → точное нормализованное ФИО → алиасы; неоднозначное → «Нужна проверка» (решения на странице импорта). Колонки хранятся по
названию (перестановка колонок не ломает синхронизацию; переименованная колонка требует нового сопоставления — синхронизация остановится с сообщением).
Идемпотентность: повторная синхронизация без изменений в таблице даёт «создано 0, обновлено 0, без изменений N». Дубликаты внутри листа — в замечания, не создаются.
Сотрудник, которого источник приносил раньше, но которого теперь нет в листе, **не удаляется и не деактивируется**: ему ставится `missing_since`, в «Качестве данных»
появляется замечание `SOURCE_EMPLOYEE_MISSING`; при возвращении в таблицу замечание закрывается автоматически.

### 8.5. Безопасность
Ключ — только на сервере; токен Google живёт в памяти процесса; все операции записи идут под пользовательской сессией (RLS, `can_import`); service-role не используется.
Права: подключать/синхронизировать — ADMIN, ACADEMY_MANAGER, HR; выбирать участников и создавать обучение — ADMIN, ACADEMY_MANAGER. Анонимного доступа нет.

Как завершить существующий импорт (без нового файла и повторной загрузки 2646 строк):
1. Применить M27 (после ревью). Открыть `/imports/<id>` — блок «Завершить применение» → «Шаг 1. Сопоставление оргструктуры из файла».
2. Сверху — доказательство причин: сколько уникальных значений и строк в каждой причине (нет нигде / есть у другого департамента / написание занято другим / неактивно / похоже / сначала департамент) и сколько строк с кодом проверки сотрудника.
3. По каждому значению выбрать действие: «Сопоставить в этом импорте» (контекстное, ничего не меняет в справочнике), «Закрепить написание» (глобальный псевдоним), «Создать новое» (только если такого нет; омоним — с подтверждением). Подсказки «похожие» ничего не объединяют.
4. «Предпросмотр» — сколько значений допустимо, сколько строк затронуто, сколько написаний/подразделений будет добавлено, что отклонено и почему. Ничего не сохраняется.

6. «Применить готовые» → причина → адаптивные пакеты (как в M26), прогресс, итог: создано / обновлено / без изменений / осталось нерешённых / дубли в файле / ошибки.
