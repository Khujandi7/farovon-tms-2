# Rollback-скрипты Phase 1.5

Файлы **не** лежат в `supabase/migrations/`, поэтому CLI и `apply_migration` их не применяют.
Они нужны для локальной проверки и для отката, пока в таблицах нет данных. Применённую миграцию
не редактируют: исправление делается новой миграцией «вперёд».

Откатывать строго в обратном порядке: `09 -> 08 -> ... -> 01` (09 = Phase 2.2, M9: `drop trigger profiles_self_protect`).
`bash supabase/rollback/verify_rollback.sh` проверяет локально: миграции вперёд, откат назад,
отпечаток структуры равен отпечатку Phase 1 (после 0004).

Ограничения:
- `07` и `03` необратимы без потери данных, если уже есть отзывы / архивные тренинги / сторно: перед откатом перенесите данные.
- Откат 01 возвращает `app_role()` без `is_active` и удаляет аудит-триггеры; записи `audit_log` остаются.
